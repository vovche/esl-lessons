# Оновлення старого offline-кешу: 9 клас

Перевірено 18 жовтня 2026 року, завершення близько 20:45 UTC. Відтворено дефект неатомарного встановлення старої схеми кешування. Виправлення з окремим кешем `esl-missions-v2` пройшло **4 із 4** браузерних сценаріїв, зберігши прогрес гри й готовність offline після оновлення.

## Підтверджений дефект до виправлення

Реальне оновлення `8a3205ae270ed50630b9c125d716d9a23134f676` → `673445eba4ed26a457b8024dfa34283f3098bf60`, на тому самому origin і в тому самому профілі: під час встановлення нової версії сервер навмисно повертав HTTP 503 для `assets/lesson-simulations.css`. Новий worker не міг завершити install, але попередні послідовні записи вже замінювали файли в активному `esl-missions-v1`.

У Chromium і WebKit, на gerund та future-v2, кешований `assets/offline-simulations.js` змінив SHA-256 з `4e9cddc09687d3cc06a5dc04f533c4dfbcf30500b4eed4226236296207a967bf` на `a917af0f07fe01b3807998e2e3bb0ff1a6656b7021617ad96f7634537a543fc5`, хоча install завершився невдачею. Отже неповне оновлення змінювало активний bundle. У цій конкретній вибірці localStorage та активна гра **не втрачалися**; фактичну втрату прогресу чи непрацездатність усього offline-програвача не стверджуємо. Дефект — відсутність ізоляції неповного install від робочого кешу.

## Двоверсійна fixture

Це браузерна перевірка локальної двоверсійної HTTP-fixture, не повторний тест свіжого кешу й не тест уже розгорнутого GitHub Pages. На одному origin сервер спочатку віддавав файли незмінного git `8a3205ae`, а після явного перемикання — іншу версію. Ні профіль, ні localStorage, ні cache між версіями не очищалися.

- Baseline origin: `http://127.0.0.1:44483/`, маршрути `/9/gerund/` і `/9/future-forms-v2/`.
- Fixed origin: `http://127.0.0.1:39095/`, ті самі маршрути. Для кожного engine/маршруту був окремий початково свіжий persistent profile, збережений протягом усього оновлення.
- Chromium / Pixel 7 mobile-touch emulation; WebKit 26.5 / iPhone 13 mobile-touch emulation. Це не фізичні Android Chrome або iOS Safari.
- Дані й ключі бралися з JSON тієї версії, яку віддавала fixture. Кнопки запуску, вибору відповіді, підказки, паузи та переходу натискалися `tap()`; select — `selectOption()`, текст — `fill()`.
- Перед fault-injection старий worker був встановлений і показано ready. Network-offline після оновлення реалізовано серверним закриттям з’єднань для всіх site-запитів, без `context.setOffline` / WebKit `offline:true`.

Для fixed-прогону worker і п’ять core-файлів з working tree зафіксовані в пам’яті fixture перед запуском: подальші паралельні зміни не могли змішати ці файли під час install. Ідентифікатор перевіреного SW: SHA-256 `094d917c979f6b7f74e5bdd6af1627ad1918633ffe119f9c1d2fb2a3218589f1`; runtime місій — `46802867e4a84b7dbc1f67232dac06df9c5b275e7d1ddbbcfdc3d43359b6fc35`; offline runtime — `a917af0f07fe01b3807998e2e3bb0ff1a6656b7021617ad96f7634537a543fc5`.

## Перевірений стан і послідовність

Для кожної ситуації спочатку у старій версії завершено самостійну місію з першою помилкою та другим правильним ходом: результат **1 із 2**, збережено унікальну чернетку `Upgrade draft [engine] [slug]`. Потім відкрито навчальну місію, зроблено помилковий вибір, показано підказку й увімкнено паузу. Збережено повний localStorage та SHA кожного запису старого кешу.

На цій активній грі викликано `registration.update()` із 503 CSS; порівняно кеш і localStorage. Далі знято 503 та повторено update до активації. Без перезавантаження гра залишилася на паузі, localStorage не змінився. Після цього **одразу заблоковано всі запити та перезавантажено оригінальний URL**, без нового online-виклику «Відкрити місії». Offline-навігація спрацювала завдяки перенесеному JSON. У shell відновлено вибрану ситуацію, паузу, підказку, завершену самостійну місію, результат і точну чернетку.

Після fixed upgrade фактично залишилися обидва кеші — `esl-missions-v1` та `esl-missions-v2`. Порівняння cached offline-runtime SHA підтверджує, що після reload використовувалася вже нова версія, а не лише неушкоджений старий програвач.

## Докази й межі

Тимчасові runner-файли: `/tmp/grade9-cache-upgrade/baseline.cjs` та `fixed.cjs`; результати/HTTP-журнал — `baseline-results.json` і `fixed-results.json`. PNG для кожного engine/маршруту — у тій самій директорії. Візуально оглянуто WebKit gerund та Chromium future після fixed upgrade: результат, чернетка, кнопки й offline-пояснення читабельні. Тимчасові файли не публікувалися й не додавалися до репозиторію.

Покриття: 2 engines × 2 маршрути для baseline і ті самі 4 fixed-сценарії. Перевірено навмисний 503 одного середнього core-файлу та наступне успішне встановлення. Не перевірялися всі можливі точки розриву, квота/витіснення cache, пошкоджений JSON кожного виду, одночасне оновлення кількох вкладок, оновлення через GitHub CDN або фізична втрата живлення. Довгострокове видалення застарілих кешів не оцінювалося. Повний process-restart — окрема перевірка у `MOBILE_RESTART_REVIEW.md`; у цьому тесті мета — двоверсійна міграція в тому самому живому профілі.

Зміни shared runtime / SW у цьому потоці не вносилися. Дефект повідомлено root; root надав виправлений snapshot для незалежного повторного тесту.
